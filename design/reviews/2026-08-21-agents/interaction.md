# UI/UX Review — Review Queue: interaction correctness & review-flow usability

Scope: desktop 1280×800, live UI at `#/memory/review` driven via Playwright. Sources: `src/tools/memory/Review.tsx`, `ClaimDetail.tsx`, `store.ts`, `facets.ts`. Items already in BACKLOG.md (mobile round, tap targets, missing search, cluster actions, blocker-list, conflict resolution, re-extract cost confirm, rejected-suggestion actions) are not re-reported. Blocked-drafts and apply-failure cards were not exercisable (0 blocked drafts in this corpus; exercising Failures requires Apply) — those get code-read-only notes.

## Findings

- **[critical] [bug]** Unsaved edit text leaks between claims and can be saved onto the wrong claim. Typed into a Sherlock `append_section` claim's textarea, clicked the next `append_section` row: its textarea showed the first claim's edited text verbatim (same 101-char value, Save enabled) — `ClaimDetail`'s `drafts` state is keyed by section id (`"__text"` for every append/update row) and the component isn't keyed by `row.key`, so state survives row switches. One click on Save writes claim A's text as claim B's pending edit. Fix: `<ClaimDetail key={row.key} …/>` or key drafts by `row.key + sectionId`.

- **[high] [bug]** Keyboard decisions land on invisible, filtered-out rows. With the Undecided quick chip on, `a` on the last row removes it from view but the cursor stays on the hidden row; the next `d` silently flipped that hidden row keep→drop (only dock numbers moved), and with a fully empty filtered list ("No proposals match…") pressing `a` still recorded a keep on an off-screen row. Cause: `cursorRow()` looks up `rows.value`, not the filtered list, and `move()` clamps onto stale keys. As a bonus symptom, after deciding the hidden row the cursor teleports to the top of the list. Fix: resolve the cursor against `visibleKeys` (advance to nearest visible neighbor when the cursor row is filtered out; no-op when empty).

- **[high] [bug]** Single-key shortcuts hijack focused buttons — Space on a focused chip mutates an unrelated claim, Enter on a chip is swallowed. Tabbed to the "Undecided" filter chip and pressed Space: the chip did not toggle, but the cursor row's decision cycled to keep; Enter likewise did not activate the chip (its keydown-click is `preventDefault`ed and instead re-opens the cursor row's detail). `onListKey` only exempts INPUT/TEXTAREA/SELECT, not BUTTON. Keyboard users cannot operate any chip, and Space is actively destructive. Fix: bail out of `onListKey` when `ev.target` is a button (or scope single-key handling to the roving list item).

- **[high] [bug]** Explicitly dropping a `create_note` while keeping its dependent `add_link` produces a contradictory, wrong dock — and the promised warning never fires. Kept the `add_link → timeline_revision_64af50` and dropped the create that makes that note: the dock still read "3 ready · **1 added as dependencies** · Apply decided (4)" — it claims the dropped create will be auto-applied, counts it twice (once in ready, once as drop), and the "kept claims depend on a dropped create" warning stayed absent. Cause: `droppedDependencyWarnings` matches on `row.targetId`, but an add_link row's targetId is the link *owner* (char note), not `mutation.link.target`; and preflight runs against keeps only, blind to local drops. On Apply this would skip the create then send an accept whose id list includes the now-deleted create. Fix: include `mutation.link.target` in the dependency check, and reconcile `readyMutationIds` against local drops before counting/sending.

- **[medium] [bug]** Escape does not close the facet sheet once focus is inside it — BACKLOG marks "Esc dismisses the sheet" as done, but it's focus-dependent. After clicking a facet value (focus on `.facet-row`), Escape did nothing; the handler lives on `.audit-list`'s `onKeyDown` and the sheet is rendered outside it. Fix: key handler (or `keydown` listener) on the sheet itself.

- **[medium] [bug]** Escape never closes the NotePeek dialog. Opened a peek from the stored block, pressed Escape: peek stayed open; only × or scrim-click closes it, and focus is not returned to the trigger (`NotePeek.tsx` has no key handling). Violates DESIGN §3 "Escape closes/back" for a `role=dialog`. Fix: Escape-to-close + focus restore in `NotePeek`/`FacetSheet` shared scrim code.

- **[medium] [bug]** Trailing decisions are silently lost on tab close — the ledger has no unload/blur flush. Decisions made within ~700ms of closing the page never reached `/console/state` (three whole test sessions persisted nothing; savedAt stayed stale), because `persist()` is a trailing debounce with no `beforeunload`/`visibilitychange` flush. DESIGN §2 specifies "debounce ~700ms, **flush on blur**". Fix: flush pending persist on `visibilitychange`/`pagehide` (e.g. `navigator.sendBeacon`).

- **[medium] [usability]** Undecided claims can be transmitted via auto-include with zero row-level indication, and "N added as dependencies" doesn't say which. With the create undecided and its add_link kept, the dock read "15 undecided … 1 added as dependencies" — the store's own contract says "undecided claims are never sent", yet this one will be, and the row carries no marker, name, or link. Fix: badge auto-included rows (e.g. "will be sent as dependency") and make the dock phrase enumerable (click → highlights the rows).

- **[medium] [usability]** Preflight latency makes the dock illegible right after deciding: for ~1.2s (500ms debounce + request) the button reads "Apply decided (0)" and is disabled with no pending indicator, then the number jumps. A user's first keep looks like "nothing will apply". Fix: show "checking…" (per DESIGN §3, indicator delayed ~100ms) and keep the count blank rather than 0 while `pf` is null.

- **[medium] [usability]** The facet sheet can render as a completely blank pane, and active filter values can become un-clearable from the sheet. With the Conflicts quick chip on (0 matches in this corpus), opening Facets showed an empty dialog — no facets, no explanation, and the active "has conflicts" value isn't listed (zero-count facets are dropped), so the sheet's only useful control is Clear-everything. Violates DESIGN §4 empty-state rule. Fix: always render actively-selected values (count 0) and give the sheet an empty-state line.

- **[medium] [usability]** "Discard changes" is destructive with neither undo nor confirm. Clicking it permanently deleted the saved edit (undo stack covers decisions only) — against DESIGN §2 "undo over confirm". Fix: route `setEdited` through the undo stack or offer an undo toast carrying the discarded text.

- **[medium] [usability]** Dock copy is self-contradictory: after one keep and one drop in different drafts it read "2 drafts will be sent · 2 stay pending" — the *same* two drafts, because `stayPending` counts touched drafts that still contain undecided claims. Reads as nonsense to a user. Fix: "2 drafts sent partially · undecided claims stay pending" or similar.

- **[low] [bug]** No-op actions pollute the undo stack, making the first undo appear dead. `x` on an already-undecided row (and `a` on an already-kept row) pushes a snapshot identical to current state, so the next `u` visibly does nothing and toasts "Undid undecide". Fix: skip `snapshot()` when the value is unchanged.

- **[low] [usability]** Undo toast wording and stacking: five rapid `u` presses piled five toasts ("Undid undecide", "Undid drop"…) simultaneously; "Undid undecide" (= re-applied a decision) is genuinely confusing. Fix: coalesce/replace the undo toast and name the restored state ("Restored drop on …").

- **[low] [usability]** Keyboard `u` with an empty stack gives no feedback, and after undoing your last decision the whole dock (with the only visible Undo button) disappears while the stack may still hold entries. Fix: toast "Nothing to undo"; consider keeping the dock while `canUndo`.

- **[low] [usability]** Sort/group changes preserve the cursor key but never scroll it into view — after switching risk→confidence the focused row sat ~300px above the viewport (`inView: -294.5`), so the next `j` acts from an off-screen anchor. Fix: `scrollIntoView` the cursor row after group/sort changes.

- **[low] [usability]** A saved edit is invisible in the list row's text: the row keeps rendering the original claim text with only a "the edited change" tag (`ClaimRow` uses `r.text`, never `edited`), and dropping an edited claim still counts it in the dock's "1 edited" although drop discards the edit — with no warning at either point. Fix: render edited text (or a strike/replace treatment) in the row, and exclude dropped rows from the edited count or warn on drop-of-edited.

- **[low] [missing-interaction]** The desktop detail pane can't be cleared or closed and goes stale: Escape is mobile-only, and when filters empty the list the pane keeps showing a claim that is no longer in view with no "filtered out" indication. Fix: Escape clears `detailKey` on desktop too; show a note when the open claim isn't in the current slice.

- **[low] [missing-interaction]** Tab order and discoverability diverge from DESIGN §3: every row's tri button, mid button, and every chip is its own tab stop (no roving tabindex — dozens of stops per screen), and there is no `?` shortcut cheat sheet anywhere in the shell (only Cmd-K is bound); the shortcut hint only appears in the detail pane's empty state. Fix: roving tabindex on the list; add the `?` overlay.

- **[low] [missing-interaction]** (code-read; 0 blocked drafts in the test corpus so not exercisable live) The blocked-drafts card's re-extract button has no busy/disabled state: `reextract` awaits N sequential model-costly extract calls with the button still enabled — a second click double-fires the batch, and there's no per-item progress. Distinct from BACKLOG's cost-confirm item. Fix: disable with a determinate "extracting i/N" while the loop runs.

## What worked well (verified, no findings)

j/k clamp correctly at both ends and `k` from nothing lands on the last row; a/d auto-advance; space cycles tri-state in both the rail and via keyboard with correct aria-labels; group Keep/Drop with per-group ✓/✗ tallies and toast-Undo round-trips cleanly; facet counts correctly exclude each facet's own filter (verified numerically), OR-within/AND-across works; "stored · n" reveals stored sections with a working open-note peek; peek links replace rather than nest; cross-session resume of the ledger works when the flush lands; sheet-header Clear keeps the sheet open; rejections group/expand correctly; zero console errors throughout.
