## A · decision and apply correctness — priority 0

1. **Cross-claim edit-text leak** [interaction critical] — nothing keys
   ClaimDetail by row, so `drafts["__text"]` survives row switches. Claim A's
   edited text then appears in claim B's editor, and Save can write it there.
   Fix: `key={row.key}`.
   **[SHIPPED — `Review.tsx` renders `<ClaimDetail key={detailRow.key} …/>` in both the desktop pane and the stacked screen.]**
2. **Stale preflight ignores local decisions** [code-scan high + interaction
   high] — Apply uses a debounced, unawaited preflight snapshot. A keep→drop
   flip inside 500ms sends a just-skipped id to accept, and the whole draft's
   accept fails. Dropping a create while keeping its dependent add_link
   miscounts the dock, and the dropped-dependency warning misses link targets,
   since nothing checks `mutation.link.target`. Fix: await a fresh preflight
   in `applyDecided`, intersect `readyMutationIds` with current keeps, include
   link targets in the warning.
   **[`OPEN` — half of this shipped. `applyDecided` awaits `preflightNow()`, which cancels the debounce, and filters `dropIds` out of the ids it sends, and the warning now checks `mutation.link.target`. The dock still adds `pf.ready` to `c.drop` without reconciling either with local drops, so it counts an autoincluded dropped create twice.]**
3. **Keyboard decisions hit invisible rows** [interaction high] — the cursor
   resolves over unfiltered rows. With filters on, `a` and `d` mutate
   filtered-out rows, or rows of an empty list, with no visible sign. Fix:
   resolve the cursor through `visibleKeys`.
   **[SHIPPED — `cursorRow()` requires the key to be in `visibleKeys`, and `decideAndAdvance` chooses its successor from that list.]**
4. **Space and Enter on focused chips hijacked** [interaction high] —
   `onListKey` exempts only `INPUT`, `TEXTAREA` and `SELECT`, so Space on a
   focused filter chip cycles an unrelated claim's decision. Fix: bail when
   the target is a `BUTTON`.
   **[SHIPPED — `useRovingFocus`'s `ignore()` bails when the target is a button outside `.mem-row` and the key isn't a nav key.]**
5. **`skippedMutationIds` ignored on accept** [code-scan high] —
   partial-success accepts mark every submitted id applied, so server-rejected
   mutations vanish for the session, since nothing clears `appliedThisSession`.
   Fix: honor the field.
   **[SHIPPED — `applyDecided` subtracts `res.skippedMutationIds` and marks only ids the engine reports applied.]**
6. **Ledger loss windows** [interaction + code-scan med] — nothing flushes on
   `pagehide` or `visibilitychange`, so the trailing 700ms debounce loses the last
   decisions on tab close. A remount within the debounce also clobbers unsaved
   decisions through `loadPersisted`. Fix: flush on hide with sendBeacon, and
   skip the load while dirty.
7. **Undo-stack hygiene** [interaction low + code-scan low] — the stack
   survives Apply and misfires onto applied keys. No-op decisions also push
   identical snapshots, which makes the first undo look dead. Fix: clear on
   apply, and skip no-op snapshots.
8. **Small server and store faults** [code-scan med] — a malformed state `PUT`
   returns 500 rather than 400. The Vault archive-undo `PATCH` has no
   `.catch`. A stale focus-source key survives a failed refresh and misfires
   later.

## B · mobile fundamentals — priority 0 and 1

9. **Tap never opens claim detail** [Luma + linkage high + mobile critical] —
    `focusRow` gates `detailKey` on desktop, so touch can't reach the detail
    surface at all. Fix: open the stacked detail on a mobile tap.
    **[SHIPPED — the roving-focus `onFocus` sets `detailKey` unconditionally, verified by tap at 486x1085.]**
10. **Hardware back exits the app** [linkage + mobile high] — stacked detail,
    facet sheet and peek push no history, so an Android back gesture
    mid-triage leaves the console. Fix: overlay history integration, which
    pairs with D32 deep links.
    **[SHIPPED — `src/shell/overlays.ts` pushes a history entry per overlay and closes on `popstate`. Verified that browser back closes the facet sheet without leaving the route.]**
11. **Escape contract broken inside overlays** [interaction + linkage + mobile
    high] — the only key handler sits on `.audit-list`, so Esc does nothing
    with focus inside the sheet or detail. NotePeek never closes on Esc, and
    never traps or returns focus. Fix: a document-level overlay stack owning
    Escape and focus.
    **[SHIPPED — a capture-phase document Escape handler in `src/shell/overlays.ts` drives the same stack, and `NotePeek` now renders through `<Sheet>`, which registers itself and restores focus.]**
12. **Density: 4 rows per screen, target ~10** [mobile high + Luma] — 96px of
    scaffolding per group (grouphead plus keep/drop action row), most groups
    holding one row. Chrome eats 26% of the screen. Fix:
    fold group actions into the head, and suppress them for single-row groups.
    **[SHIPPED — group actions folded into the head and rows are 41px. Re-measured 8 fully visible (9 partial) at 390x844, with no `.group-actions` left in the list.]**
13. **Mobile chip rail → three buttons** [Luma] — [Filter] [Group by]
    [Sort by], plus sort direction. Today the group and sort chips sit 1-2
    screens off canvas with no scroll affordance [mobile low]. Open question:
    which quick chips survive inline (interview Q7).
14. **Facet sheet doesn't fit, and Clear scrolls away** [Luma + mobile med] —
    980px of content in a 657px sheet, with a header that isn't sticky within
    the sheet. Fix: sticky sheet header and tighter rows. Consider per-facet
    collapse.
15. **Apply dock occludes** [mobile med] — on a phone the dock covers the
    bottom tool rail entirely, so you can't switch tools while decisions
    exist. It also overlaps the desktop rail by 20px (dock 64px, rail 84px).
    Fix: put the dock over the rail on mobile, and fix the offset.
16. **Undo has no touch path when the dock hides** [mobile med] — only the
    dock offers a touch Undo, and it unmounts at zero tally. Fix: an undo toast on
    bulk reset, and keep the dock while `canUndo`.
17. **Sticky groupheads hide under the console** [mobile med] — a z-index and
    top collision leaves the pinned context header invisible mid-scroll. Fix:
    a top offset.
18. **Export glyph is tofu on phone** [mobile low] — U+2B73 is missing from
    every loaded face.

## C · visibility of computed state — priority 1

19. **Preflight runs unannounced, and the button reads (0)** [visibility high
    + interaction med + mobile low] — no pending indicator during the debounce
    and round trip, so the first keep looks like nothing will apply. Fix: a
    `preflightPending` signal, and checking copy.
    **[SHIPPED — `preflightPending` drives a "checking with the engine…" line and an "Apply decided (…)" label.]**
20. **Autoincluded dependencies unenumerable** [visibility high + interaction
    med] — `N added as dependencies` names no rows, and undecided claims go
    over the wire with zero row-level indication, contradicting the store's
    own contract copy. Fix: an expandable dock phrase, plus a row badge
    reading `sent as dependency`.
    **[SHIPPED — `preflightRowState` maps preflight rows back to row keys, the dock enumerates autoincluded and blocked rows in `<details>`, and rows carry a "dependency" tag.]**
21. **Meter denominator includes undecidable claims** [visibility high +
    code-scan med] — `counts.mutations` in the header includes blocked
    drafts' rows, while the dock uses decidable rows. Same word, two
    numbers. Fix: `rows.value.length`.
    **[SHIPPED — the meter's total is `rows.value.length`.]**
22. **Meter is color-only** [visibility med] — `1 · 0 / 17` in emerald and
    red. Pair the glyphs as `✓1 · ✗0 / 17` (`WCAG` 1.4.1, DESIGN §1).
23. **Ledger state invisible at rest, and failure unrecoverable**
    [visibility med x2] — `Saved` never shows. `Save FAILED` is dim header
    text with no retry and no toast. Fix: a persistent save pill and a retry
    affordance.
24. **Blocked card names nothing** [visibility + linkage med] — source titles
    go unused, held claims stay invisible, re-extract semantics go unstated.
    The button has no busy state either, so it double-fires [interaction low].
    Fix: per-source rows with NoteRefs, plus a busy state. (The cost confirm
    is already in the backlog.)
25. **Index health is inert** [visibility med cluster] — a rebuild failure
    goes out as a toast and nothing else, where the journey table wants a
    persistent `saved, not searchable` badge. No rebuild affordance exists anywhere. Header counts go
    stale after import or apply, since the effect keys on view [code-scan
    low]. A status fetch failure blanks the line, and
    `embeddingsAvailable:false`, a dead recall lane, never surfaces.
26. **Apply progress is a button label** [visibility med] — a sequential
    multi-draft loop with no per-draft progress. Fix: `draft 2/5` in the dock.
27. **Pressure numbers never reach the screen** [code-scan + visibility med] —
    the full current/projected map gets computed, and only a boolean chip
    ships. Fix: `19.4k → 21.3k / 20k` on target group heads and in
    ClaimDetail, and wire `nearLimit` at ≥0.8.
28. **Sources previews load blank, and imports are a button label**
    [visibility med x2] — render kind headers immediately with `scanning…`
    placeholders, and stream per-source import results (`Importing 2/5…`).
29. **Staleness passes unannounced** [visibility low] — `generatedAt` and
    engine dedup counts arrive and never show. Review and Sources have no
    refresh affordance.
30. **Restore-point failure invisible** [code-scan med] — nobody reads the
    `x-ltm-restore-point: failed` header. Fix: check it in `api()` and toast
    once.

## D · linkage and navigation — priority 1 and 2

31. **Vault note → related claims missing** [linkage high] — "pruning here is
    what unblocks the queue", says the editor, which offers no path to those
    claims. Fix: a `related claims (n)` affordance leading to review,
    pre-filtered by target.
    **[`OPEN` — `NoteEditor` still ends at links, dedupe, save, archive, and delete. Nothing navigates to the claims that target the note.]**
32. **No object has an address** [linkage med] — there's no
    `#/memory/vault/:noteId` and no review claim deep link. That's the root
    cause of the back-button trap, the peek dead-ends, and Cmd-K having
    nothing to target.
33. **NotePeek dead-ends** [linkage med x3] — no open-in-vault, no back stack
    for chained peeks, and no reverse-links section, though every note is
    already client-side.
34. **create_note target is a dead 404 link** [linkage med] — peek the
    *proposed* note out of `m.note`, or render a `will be created` chip.
35. **Sources never links onward** [linkage med] — outside the transient
    import card there's no pending-drafts count leading to review, and no
    NoteRef to the imported source note. The word *review* never appears on
    the surface.
36. **Review tab click wipes facets** [linkage med] — a hidden destructive
    side effect on a nav control. Remove it, and ship removable filter chips
    instead, with 37.
37. **Active filters invisible outside the sheet** [linkage med] — the handoff
    filter shows only `7 of 17`. Render active facet values as removable
    chips (DESIGN §4).
38. **Vault forgets everything on a tab round trip** [linkage med] — useState
    where Review uses signals, so the prune-then-retry errand pays twice. Fix:
    hoist to signals.
39. **Small linkage** [linkage low x3] — group heads aren't linked to their
    object, status-line counts navigate nowhere, and the restates link shows a
    raw id rather than a title.

## E · copy and semantics — priority 2

40. **Tab badge counts drafts and sits beside claim counts** [Luma +
    code-scan] — show pending claims instead, to match the meter.
41. **Wrong-journey empty states** [visibility med x2 + interaction med] — the
    Review empty state uses a Sources string, and a Vault zero-result search
    shows the vault-is-empty onboarding. The facet sheet can render fully
    blank, since it drops active zero-count values, which also leaves those
    filters with no individual Clear.
42. **`N will be sent · M stay pending` double-counts** [visibility +
    interaction med] — the same draft lands in both numbers. Rephrase as sent
    in part, undecided stays pending.
43. **Vault promises `create a memory manually`** [code-scan med] — no create
    affordance exists, and no `POST /notes` binding. Swap the copy or build
    the feature.
44. **Permanent-delete confirm uses source-note copy for every type**
    [code-scan med] — `keep its extracted memories` is false for a character
    note.
45. **Staged-edit toast says `Saved`** [visibility low] — say `Edit staged —
    applies with the batch`. The row also doesn't render the edited text, and
    dropping an edited claim discards the edit without a word while still
    counting it [interaction low].
46. **`Discard changes` destroys the edit with no undo** [interaction med] —
    route it through undo, or toast the discarded text.
47. **Freshness chips and `N ready` map to nothing** [visibility med x2] — the
    chips name states rather than obligations, and `3 scanned · 1 ready` maps
    to no row marking.
48. **Chat-summaries zero explains the feature, not the zero** [visibility
    med] — J1 asks it to explain the emptiness and when to return.
49. Small copy: `23 match` needs pluralization, RESTATES is a bare score on
    rows, undo toast wording and stacking need work, and a hardcoded `over the
    limit` bypasses the `OURS` catalog [code-scan].

    cross the list, where DESIGN §3 mandates one stop per composite.
    **[`OPEN` — `useRovingFocus` moves the cursor and leaves every row control tabbable. Measured 279 tab stops inside `.audit-list`.]**
51. **No `?` cheat sheet** [mobile + interaction med] — only the empty detail
    pane teaches the a/d/x/space/u vocabulary.
52. **Focus ring invisible on the active rail item** [mobile med] — a
    specificity bug.
53. **Dialog semantics incomplete** [mobile low] — no aria-modal, no focus
    move-in or restore, and stack-screen has no role. The badge also
    concatenates into the tab's accessible name (`Review Queue2`).
54. **The desktop detail pane can't close and goes stale under filters**
    [interaction low].
