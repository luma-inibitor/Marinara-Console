Viewing one memory — how the view varies by type

Mockup round 1 · 2026-08-23 · content read from the seeded corpus, not written for the page

31 notes · 7 types · measured, not guessed

The question this round answers: does each memory type need its own view, or one view with a per-type configuration? The corpus says the second. The chrome is identical across all seven types; the only thing that varies is the section area, and it varies by shape — how many sections, how long — rather than by type name.

M1One component, six types

Every type gets the same chrome: type glyph and hue, title, status, mode pill, updated stamp, links, keywords, raw id. Only the section area changes. That is the finding — the types differ in what sections they carry and how long those sections run, not in what surrounds them. Source needs folding and the other six do not. Folding a 96-character timeline event hides nothing and costs a click. The fold threshold should be a property of the text length, not of the type.

A data finding, not a design one. Tone's two sections are near-duplicates in every note in the corpus: §observations reads "Scenes in the lower town run slow and close, with weather doing half the talking." and §profile reads the same sentence with a "Tone profile: " prefix and a doubled full stop. Showing both faithfully means showing the same sentence twice. Worth checking with the engine before designing a two-section layout around it.

B is the one that respects the settled rule that a collapsed header still carries data — each fold names its section and its size, so closed is not invisible. It is also the only one that keeps links and keywords on screen for a five-section character. A is right for the four single-section types, where B would add a fold that hides nothing. C reads as one column of prose with an index down the side — fastest to skim, worst to edit, because there is nowhere to hang a per-section control and the character counts are gone.

Which suggests the rule is not per type but per shape: one section renders as A, more than one renders as B, and the lead section is whichever the type names as required — core for character, observations for tone. That is a config table of two columns, not six components.
