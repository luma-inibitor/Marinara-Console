# Design-sync notes

## Repo shape

- **No Storybook, no `*.stories.*`** → `shape: "package"`.
- **This is an app, not a published library.** `package.json` has no
  `main`/`exports`/`module`/`types` field. The real component surface is
  **`src/ui/index.ts`** — a barrel with 23 exports over 22 components. The
  converter needs that pointed at explicitly. Discovery won't find it.
- **`dist/` is a Vite app build** (index.html + hashed assets), not a component
  library build. Don't treat it as the compiled component output.

## Invocation — the flag without which nothing builds

    node .ds-sync/resync.mjs --config .design-sync/config.json \
      --node-modules ./node_modules --entry ./src/ui/index.ts \
      --out ./ds-bundle --remote <anchor.json>

**Pass `--entry ./src/ui/index.ts`.** Without it the converter resolves the
package as `<node-modules>/<cfg.pkg>` and dies on
`node_modules/marinara-console/package.json: ENOENT`. This is an app, so npm
never installs it into its own node_modules. With `--entry`, the converter
walks up from the entry to the first `package.json` carrying a `name`, which
lands on the repo root. Don't "fix" the ENOENT by symlinking the repo into its
own node_modules. The repo contains `.ds-sync/`, so that link is a cycle, and a
recursive copy through it empties real directories in the repo.

`--node-modules ./node_modules` is now the repo's own. It carries react since
the port, so the separate scratch install is no longer needed.

## Runtime

The console runs **React 19**, with no `preact` or `@preact/signals` installed.
Nothing vendors a compat shim, so the bundle ships the same React the design
pane renders.

## Install

**Don't run `npm ci` while other work is in flight.** It wipes `node_modules`,
and concurrent agents build on it. Deps are already installed and
lockfile-consistent. `npm ci` is correct for a cold clone only.

npm's optional-dependency bug bit this repo once: a missing
`@rolldown/binding-darwin-arm64` broke Vite. Fix it with
`npm i --no-save @rolldown/binding-darwin-arm64`.

## Why the graph is bigger than src/ui

`src/ui/ErrorState.tsx` imports `ApiError` from `src/shell/api.ts`, so bundling
the barrel pulls in `src/shell/`. Expect the bundle to span more than
`src/ui/`.

## Components outside the bundle

`JsonView` and `CollapseButton` are real components, but the `src/ui/index.ts`
barrel no longer exports them (only `src/ui/` consumes them). They aren't
`window.MarinaraConsole.*` exports, so they can't be component cards.
`componentSrcMap` holds `null` for both. To include them, re-export them from
the barrel first. Un-nulling alone leaves their cards pointing at a missing
export.

## Known render warns (triaged)

A warn missing from this list is new.

- **`[FONT_MISSING]` for `Archivo`, `JetBrains Mono` and `Source Sans 3`** (the
  bare, non-Variable names). These aren't real misses. `tokens.css` declares
  stacks like
  `"Archivo Variable", "Archivo", system-ui, sans-serif` — the *Variable* faces
  ship (16 `@font-face` rules via `cfg.extraFonts` pointing at the
  `@fontsource-variable/*` packages), and the bare names are deliberate
  fallbacks for a locally installed static version. Validate can't tell a
  fallback from a missing family. Don't "fix" by adding static woff2s.

## Prop extraction

The converter emits `[key: string]: unknown` for every component unless it can
parse real declarations. This repo sets `noEmit: true` and ships no `.d.ts`, so
out of the box **all 22 contracts were empty**. That leaves the design agent no
API to build on, which is the most valuable thing in the upload.

Fix, and it must be redone whenever component props change:

```sh
npx tsc -p tsconfig.dts.json          # emits .ds-sync/types/ (gitignored)
```

Then regenerate `cfg.dtsPropsFor` from those declarations. `tsconfig.dts.json`
sits at the repo root. The generator matches
`export declare function Name(props: {…})`. **`Edu` destructures its params**
(`function Edu({ children }: {…})`), so the config carries it by hand. Any
future destructured component needs the same treatment.

The generated bodies map `ComponentChildren` → `React.ReactNode` and
`JSX.Element` → `React.ReactElement`. The source says `ReactNode` directly, so
the emitted and configured bodies agree without translation.

Checking for drift is mechanical: match `declare function <Name>(props: {…})`
in `.ds-sync/types/**` with `cfg.dtsPropsFor` and compare the property-name
sets. At the last sync 21 of 22 matched exactly, and only `Edu` was absent, as
it destructures. Anything else absent means a component started destructuring
and needs hand-writing too.

## CSS entry must be a concatenation, not an import list

The converter appends `cfg.cssEntry` **raw**. It doesn't follow `@import`. An
entry file containing `@import "../src/styles/tokens.css"` ships an
unresolvable import and loses every token. `.design-sync/ds-entry.css` is
therefore generated by `.design-sync/build-css-entry.sh`, which cats
`tokens.css` + `base.css` together. **Run that script before every build.**

`base.css` matters because `src/ui` components apply `.t-data` / `.t-label` /
`.t-num` / `.hit` by class name. Without it they render unstyled.

## Preview cards render on the console's own canvas — don't lose this

The generated card template ends its `<head>`, **after** `styles.css`, with a
`<style>` rule that sets the body margin to 0, its padding to 24px and its
background to white.

This console is dark-only, so on white every card rendered light text on light
and read as blank.

`build-css-entry.sh` therefore appends a rule setting the `html body`
background to `var(--canvas)` and its color to `var(--text)`. Specificity 0,0,2
beats the card's 0,0,1 whatever the order, so it needs no `!important`. A
design that wants another surface can override it the same way.
`.ds-sync/lib/emit.mjs` hardcodes the background with no config knob, so this
is the config-only way to beat it.

Symptom if it regresses: cards go white and the blank count jumps.

## Reading the render check

`[RENDER_BLANK]` is a **file-size heuristic** (<5KB), and a uniformly dark card
compresses just as small as a uniformly white one. It can't tell a broken card
from a correctly dark, sparse one. Look at `_screenshots/contact-sheet-*.png`
before believing it.

The 7 flagged components (CopyableText, DetailSection, Edu, EmptyState,
ListGroup, SheetHead, Term) are blank for a plain reason. An unauthored preview
mounts as `h(C, {})`, and those components have nothing to draw without props.
The ones that do render (ErrorState, ListEmpty, Loading, NotFound) differ only
in carrying fallback copy, and they display the literal word `undefined` where
a prop should be. Authoring previews is the fix, and the owner deferred it.

## Re-sync risks

- **Copy churn**: `.prompt.md` files quote JSDoc, which drifts. Previews are
  floor cards, so a card bakes in no copy.
- **`sourceKeys` didn't move across the React port**, so the driver reported
  22 verified-by-upload and graded nothing. Grades follow authored previews and
  preview-affecting config, not source edits, so a rewrite this large ships
  without re-grading. Read the contact sheets yourself when the source churned.
- **`dtsPropsFor` is a snapshot.** It doesn't track prop changes. Re-emit
  declarations and regenerate it on every re-sync, or contracts go stale. The
  build won't warn.
- **`.ds-sync/scratch/`** is a leftover Preact-era node_modules and is no longer
  used — `--node-modules ./node_modules` is the repo's own now. Safe to delete.
- **Preview authoring is the standing offer**: all 22 ship floor cards. A
  re-sync can add previews one at a time. Written previews live in
  `.design-sync/previews/` and carry forward.
